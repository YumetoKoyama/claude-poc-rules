## 2. マージの基本ルール

- backend 固有の記述（OpenAPI Generator 同期・生成モデル `generated.openapi.*` 運用・`references/`・Spring Security の `R-SEC-*` 観点・JaCoCo 閾値など）は **すべて保持**。
- rules 側の改善は **追加（additive）** で挿入。各挿入箇所には「**rules 改善**」と明記して由来を追跡可能にした。
- backend 固有行が「rules の旧版と同じロジックの古い実装」だけだったスキルは、rules 版（＝backend ベース＋改善の上位互換）を採用。
- 共通スクリプトは rules 版が backend の挙動（IT「対象外」許容・日本語切断検出・backend 確定表判定）を保持した上位互換だったため rules 版を採用。

## 5. 重要な注意・リスク（取り込み前に必ず確認）

1. **ハッシュ照合はペアで導入**: `review-implementation` の品質ゲート確認を「更新時刻」→「コミット/ファイルハッシュ照合」(RC-07) に変更した。これと整合させるため `implement-from-issue` 手順5に **ハッシュサイドカー出力**(`target/.gate-commit` 等) を追加済み。**この2スキルは必ずセットで取り込むこと**（片方だけだと review が常に BLOCK になる）。移行期の安全弁として、サイドカー不在のレポートは従来の時刻判定にフォールバックする一文を review 側に入れてある。

2. **state スクリプトの構造変更（互換）**: rules 版は `_state-root.sh` で state ルートを git toplevel から解決する（CWD非依存）。backend の implement/integration フェーズでは **git toplevel = リポジトリ root = 従来の `.skills-state/` 位置**で挙動互換。既存 `.skills-state/` を壊さない。サブディレクトリから起動した場合は rules 版の方が堅牢。

3. **`append-review-summary.sh` は未配線**: backend の `review-implementation` は自スキル内でレビュー結果.md を書き出す方式（手順8/8.5）を保持した。そのため loop 側に `append-review-summary.sh` は**あえて配線していない**（二重書き込み回避）。スクリプトは将来用に同梱のみ。

4. **`verify-fix` スキルを新規追加**: `implement-loop` の fix 段に verify-fix を grafт したため、rules 専用の `verify-fix/` スキルと `verify-fix-coverage.sh` を同梱。これを入れない場合は loop の verify-fix 参照を外すこと。

5. **backend 既存の切断ファイル（rules 由来ではない・要再生成）**: 反映とは無関係に、**backend 原本の以下のファイルが末尾途中で切断（壊れている）**ことを発見した。rules に同等物が無いため自動復元できない。人手での再生成を推奨:
   - `review-implementation/SKILL.md` … 本マージで rules 完全版の末尾により**修復済み**
   - `implement-from-issue/references/openapi-gen-sync.md` / `pr-template.md` / `quality-gate-outputs.md` / `test-design-draft.md` … **未修復**（backend固有・要再生成）
   - `augment-generated-models/references/completion-summary-template.md` / `use-generated-models/references/adaptation-patterns.md` / `enum-mapping-guide.md` … 対象外スキルだが同様に切断（参考）

## 6. 取り込み手順（backend 反映時）

1. 別作業の区切りで、backend リポジトリにブランチを切る。
2. `merged/.claude/skills/` を backend の `.claude/skills/` に重ねてコピー（`augment-generated-models` / `use-generated-models` は触らない）。
3. §5-1 のペア（implement-from-issue ＋ review-implementation）が両方入っていることを確認。
4. §5-5 の未修復 references 4 本を人手で再生成。
5. `bash .claude/skills/_common/scripts/*.sh` の構文と、`/implement-loop <Issue>` のドライランで state 初期化・採択ゲートが動くことを確認。
