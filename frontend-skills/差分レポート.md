# frontend スキルへの rules 改善反映レポート

/ 作成日: 2026-06-29
/ 方針: **frontend リポジトリのスキルを正（ベース）** とし、その上に **claude-poc-rules にあったレビュー・品質改善を追加マージ（additive）**。frontend は FE 規約の正典（frontend ルール最優先）のため、frontend 固有の記述は 1 行も失わないよう grafт（接ぎ木）方式を採用した。各挿入箇所には `<!-- rules 改善 ... -->` マーカーを残し由来を追跡可能にした。

---

## 1. 成果物の場所

```
frontend-skills/
├── README.md
├── 差分レポート.md                       ← 本ファイル
└── .claude/skills/                      ← frontend へ取り込む「マージ済みスキル一式」
    ├── _common/scripts/                 ← 共通スクリプト（追加2 + 更新7 + 既存維持9）
    ├── coverage-to-100/
    ├── fix-implementation/

    ├── implement-loop/                  ← TDD ファースト構造を保持
    ├── review-implementation/
    ├── static-analysis-remediation/
    ├── test-design-from-issue/
    ├── unit-test-from-design/
    └── verify-fix/                      ← frontend 既存（rules と完全一致＝対象外・そのまま同梱）
```

同じものを `claude-poc-frontend/.claude/skills/` にも反映済み。**frontend にしか無いスキルは無く**、対象 10 スキル + `_common` のみを扱った。

---

## 2. マージの基本ルール

- frontend 固有の記述（**frontend ルール最優先**・Vitest / React Testing Library / MSW・Zustand・`apiClient.ts`・ESLint / Prettier / TypeScript 型チェック・npm audit・**IT 層が無い設計不変条件**・`*.test.ts(x)` 隣接配置）は **すべて保持**。
- rules 側の改善は **追加（additive）** で grafт。各挿入箇所に `<!-- rules 改善 ... -->` を明記。
- frontend 固有行が「rules の旧版と同じロジックの古い実装」だけだったスキル（coverage-to-100 / unit-test-from-design）は、rules 版（＝上位互換・FE 値を保持）を採用。
- backend 専用概念（OpenAPI Generator / 生成モデル / migration / concurrency / Spring Security R-SEC / JaCoCo）は **持ち込まない**。

## 5. 重要な注意・リスク（取り込み前に必ず確認）

1. **ハッシュ照合はペアで導入済み**: `review-implementation` の品質ゲート確認を「更新時刻」→「コミットハッシュ照合」(RC-07) に変更した。整合のため `implement-from-issue` 品質ゲート節に **ハッシュサイドカー出力**(`coverage/.gate-commit`) を追加済み。**この2スキルは必ずセットで取り込むこと**（片方だけだと review が常に BLOCK）。**移行期の安全弁**として、サイドカー不在のレポートは従来の時刻判定にフォールバックする一文を review 側に入れてある（非破壊）。

2. **state スクリプトの構造（互換）**: rules 版は `_state-root.sh` で state ルートを git toplevel から解決する（CWD非依存）。frontend の implement フェーズでは git toplevel = リポジトリ root = 従来の `.skills-state/` 位置で挙動互換。既存 `.skills-state/` を壊さない。`init-state.sh --reset` は escalated 済み state のみアーカイブ再初期化する冪等仕様。

3. **`append-review-summary.sh` は未配線**: frontend の `review-implementation` は自スキル内でレビュー結果.md を書き出す方式（手順8/8.5）を保持した。そのため `implement-loop` 側に `append-review-summary.sh` は**あえて配線していない**（二重書き込み回避）。スクリプトは既存同梱のまま。

4. **`verify-fix` は frontend に既存**: rules と完全一致（diff 0/0）。`implement-loop` の fix 段に verify-fix を grafт したため参照が増えたが、スキル・スクリプト(`verify-fix-coverage.sh`)とも既存で追加不要。

5. **frontend の IT 層なしを尊重**: `check-test-matrix.sh` は frontend 版を維持（§4）。`test-design-from-issue` / `implement-from-issue` の「IT 層なし・RTM に IT-XXX 列なし・MSW 結合は単体扱い」記述も保持した。rules の integration 関連記述は frontend に持ち込んでいない。

6. **切断ファイル**: frontend 原本・マージ後とも、全 `.md`（SKILL.md・references・templates）が **UTF-8 妥当で末尾切断なし**であることを確認した（backend のような未修復切断ファイルは**無し**）。`implement-from-issue/references/` の3本(api-client-guide / pr-template / quality-gates)も健全。
