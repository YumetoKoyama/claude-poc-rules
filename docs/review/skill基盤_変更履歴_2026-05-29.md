## 2. 共通基盤（決定論層スクリプトとゲート）

### §1-4 人手採択ゲートの機械化（推奨以上）

- `.claude/skills/_common/scripts/approve-phase.sh` を新設。`bash approve-phase.sh <requirements|design> <承認者名>` で `.skills-state/<phase>/approved.json`（`approved: true` / approver / approved_at / git_sha）を生成。`--revoke` で取消も可能。
- 後続 skill の前提条件に「`approved.json` の `approved == true` を確認、未採択なら中断」を追記。
  - `.claude/skills/design-from-requirements/SKILL.md`（requirements 採択を要求）
  - `.claude/skills/ui-brief-from-design/SKILL.md`（design 採択を要求）
  - `.claude/skills/create-issues-from-design/SKILL.md`（requirements + design 採択を要求）
  - `.claude/skills/implement-from-issue/SKILL.md`（design 採択を要求）

### §1-5 escalation 判定の一元化

- `.claude/skills/_common/scripts/advance-state.sh`: 上限超過 escalate 判定（`iteration > max`）を削除。stage 遷移と `iteration++` のみを担当するように整理。
- `.claude/skills/_common/scripts/record-review.sh`: PASS（BLOCK==0）/ escalate（BLOCK 残存かつ `iteration >= max`）の判定を本スクリプトに集約。`>=`/`>` の二重判定による off-by-one を解消。

### §1-6 history への review イベント記録

- `record-review.sh`: review 完了イベントを `state.history` に追記（`block` / `suggest` / `nit` 件数つき）。PASS 時は `done`、上限時は `escalate` も history に記録。監査ログに review 結果が残るようになった。

### §1-7 state 内パスの相対化

- `record-review.sh`: 受け取った review JSON パスを `.skills-state/` 起点のリポジトリ相対パスに正規化して `last_review_path` に保存。`/workspace/...` のような実行環境依存の絶対パス混入を防止。

### §1-8 review/fix sub-skill のループ専用化

- 次の 6 skill の frontmatter に `disable-model-invocation: true` を追加（SlashCommand 経由のみ起動。モデルの文脈からの誤起動を防止）。
  - `review-requirements` / `review-design` / `review-implementation`
  - `fix-requirements` / `fix-design` / `fix-implementation`

### §1-9 残骸ファイル削除（NIT）

- `.claude/skills/ui-brief-from-design/test_write.txt`（0 バイトの書き込みテスト残骸）を削除。
