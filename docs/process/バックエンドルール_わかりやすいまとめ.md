# バックエンド実装ルール — わかりやすいまとめ

> `rules/backend-01〜05-*.md` の要点を平易にまとめたもの（参考資料。正典は `rules/backend-*.md` 本体）。

## 一言でいうと

**1 つの Spring Boot アプリ**の中を、**業務モジュールごと**に区切り（モジュラモノリス）、各モジュールの中身を**オニオンアーキテクチャ**（業務ルールを中心に、技術依存を外側へ）で組む。業務操作はすべて **UseCase（ユースケース）** を入口に通し、DB・通知・メール・時刻などの外部依存は **Port（インターフェース）と Adapter（実装）** で切り離す。

## やること / やらないこと

| やる（採用） | やらない（禁止） |
| --- | --- |
| モジュラモノリス（単一アプリ・業務モジュール分割） | マイクロサービス（サービス分割） |
| オニオン + Application 層に UseCase 境界 | 単純 3 層（Controller→Service→Repository だけ） |
| Port/Adapter で外部依存を分離 | 業務ロジックを Service に直書き |
| UseCase 境界の概念のみ採用 | 全機能にクリーンアーキテクチャ（InputPort/Interactor 等）をフル適用 |

---

## 4 つのレイヤーと依存の向き

各モジュールは原則この 4 層。**依存は内向きの一方通行**（外側が内側に依存し、内側は外側を知らない）。

```
presentation  →  application  →  domain
（REST入口）      （UseCase）      （業務ルール本体）
                      ↓
                    port（interface）
                      ↑
                infrastructure（JPA・通知・メール・時刻の実装）
```

- **presentation**：Controller / Request・Response DTO。業務判断は書かない。Entity を直接返さない。`@Transactional` を書かない。
- **application**：UseCase（1 クラス 1 ユースケース）。`@Transactional` の境界はここ。業務ルール本体は domain に委譲。通知は直接書かずイベント経由。
- **domain**：Entity / 値オブジェクト / Domain Service / Repository インターフェース / Domain Event。**Spring・JPA に依存しない**。`LocalDateTime.now()` 直呼び禁止（Clock 経由）。状態変更は setter でなく業務メソッド（`job.agree()`）。
- **infrastructure**：JPA Entity・Spring Data Repository・各 Port の実装。Spring 依存はここに閉じ込める。**JPA Entity と domain model は別クラス**。

## 必ず守る 10 のルール（R-ARCH）

| ID | ルール | ひとことで |
| --- | --- | --- |
| R-ARCH-001 | 機能別パッケージ分割 | `controller/ service/ repository/` の平置き禁止。`job/ bid/ deal/...` で切る |
| R-ARCH-002 | UseCase 一元化 | Web も バッチ も 非同期も、必ず UseCase を通す |
| R-ARCH-003 | バッチの DB 直更新禁止 | バッチ（別リポジトリ）は API/MQ 経由で UseCase を呼ぶ |
| R-ARCH-004 | ドメインモデル非公開 | 外部への契約は Response DTO / 公開 API のみ |
| R-ARCH-005 | Controller は薄く | UseCase 呼び出しと DTO 変換だけ |
| R-ARCH-006 | JPA Entity を API に出さない | 必ず Response DTO に変換 |
| R-ARCH-007 | Port/Adapter で外部分離 | Repository・通知・メール・Clock・外部 API は interface + 実装 |
| R-ARCH-008 | 通知の直接送信禁止 | Domain Event / Application Event 経由で発火 |
| R-ARCH-009 | 状態変更はメソッド経由 | `job.setStatus(...)` ❌ / `job.agree()` ✅ |
| R-ARCH-010 | 時刻は Clock 経由 | `LocalDateTime.now()` 直呼び禁止 |

## モジュール構成（V1）

ルートパッケージ `com.example.logisticsmatching` 配下の 9 モジュール。

| モジュール | 担当 | 内包（V1） |
| --- | --- | --- |
| `auth` | ログイン・パスワードリセット・簡易ロック | — |
| `tenant` | 企業アカウント登録・ユーザー管理・テナント境界 | — |
| `job` | 案件の登録/編集/削除/状態管理 | — |
| `bid` | 応募・上限/締切判定・セット応募 | set-bid を内包 |
| `deal` | 連絡・交渉・合意・成約・スナップショット・他応募クローズ | negotiation を内包 |
| `delivery` | 運送ステータス遷移・評価 | rating を内包 |
| `notification` | 通知の生成/一覧/既読化 | — |
| `query` | 参照系（ダッシュボード・一覧・履歴）。**domain 省略の 3 層** | — |
| `shared` | 共通識別子・Clock interface・共通例外（**業務ロジックを置かない**） | — |

### パッケージの形（job モジュール例）

```
job/
├─ presentation/   JobCommandController, request/, response/
├─ application/     CreateJobUseCase, UpdateJobUseCase, DeleteJobUseCase
├─ domain/          model/(Job, JobId, JobStatus), service/, repository/(JobRepository=interface)
└─ infrastructure/  persistence/(JobJpaEntity, SpringDataJobRepository, JobRepositoryImpl)
```

ポイント：`domain/model/Job.java`（業務）と `infrastructure/persistence/JobJpaEntity.java`（永続化）は**別クラス**。Repository は domain で interface、infrastructure で実装。

## domain をどこまで作り込むか（優先度）

全部を同じ深さで作らない。**業務ルールが濃い所は最初から厚く、参照系は軽く**。ただし依存方向だけは最初から守る。

| 優先度 | 方針 | 対象 |
| --- | --- | --- |
| **P0**（最優先・厚く） | 状態遷移・整合性制約を domain で堅く守る | 案件 job / 応募 bid / セット応募 / 合意・成約 deal / 運送遷移 delivery |
| **P1**（一部適用） | 要所だけ domain 化 | 認証 auth / テナント tenant / 最終条件提示 / 評価 / 通知 |
| **P2**（軽量） | application + infrastructure 中心 | ダッシュボード / 一覧検索 / 取引履歴（query） |

### 実装順序

案件・応募・セット応募・合意（P0）→ 運送遷移・評価・通知 → 認証・テナント → query（軽量）→ 運用後、変更が多い所から深掘り。

---

## P0 機能のレビュー時チェック

- [ ] 状態遷移ルールが Entity / 値オブジェクトに実装されているか
- [ ] 不変条件が domain のメソッド内でガードされているか
- [ ] UseCase が Infrastructure を直呼びして domain ルールを飛ばしていないか
- [ ] 同時アクセス競合が UseCase / トランザクション設計で考慮されているか
- [ ] 通知発火が Domain Event / Application Event 経由か

## よくある違反（レビュー観点）

| 違反 | どの層の問題 |
| --- | --- |
| Controller に業務ロジック / Repository 直 import | presentation |
| UseCase の中に `@Entity` や JPA クエリ | application |
| domain クラスに `@Autowired` / `@Transactional` / `now()` 直呼び | domain |
| JPA Entity を API レスポンスに直接返却 | presentation |
| 通知送信を UseCase 本文に直書き | application |
| バッチが domain を通さず Repository を直呼び | infrastructure |
