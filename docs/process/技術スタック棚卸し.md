# 技術スタック棚卸し（明示定義 / Claude 既定 の切り分け）

> ⚠️ **本書は派生スナップショット（参考）であり、技術スタックの正典ではない。** 技術スタックの正典は `rules/`（FE: `frontend-*.md` / BE: `backend-*.md`）。本書は棚卸し時点の出典分析であり、CLAUDE.md の「要件未指定時の標準スタック」節は廃止済み（→ `rules/` 参照に移行）。

> CLAUDE.md・実装スキル群・frontend ルール（あとから流し入れた正典）を横断し、**どの技術要素を誰が・どこで定義したか**を一覧化したもの。「チームが明示定義した部分」と「Claude（Claude Code）が既定・手順内で決めた部分」を切り分ける。
>
> 区分は**出典と framing から推定**したもので、各要素の採否の最終判断はチームに委ねる。frontend ルールは正典（最優先）。

## 凡例（区分）

| 区分 | 意味 | 出典 |
| --- | --- | --- |
| 🟦 **正典** | チームが明示的に定義（最優先）。 | frontend ルール（`rules/frontend-*.md`） |
| 🟩 **ルール** | CLAUDE.md の「開発ルール」本文でハード制約として明示。 | CLAUDE.md 開発ルール |
| 🟨 **既定（Claude 提案）** | CLAUDE.md「**要件が未指定の場合の標準スタック**」のフォールバック既定値。要件で上書き可能。チームが意図して固定したものではなく、Claude が埋めた既定の色が濃い。 | CLAUDE.md 標準スタック章 |
| 🟥 **スキル内決定（Claude）** | CLAUDE.md にも正典にも無く、スキル手順の文中だけで Claude が決めた。 | `.claude/skills/*` のみ |

状態欄: ✅有効 ／ ⚠️FE 正典と矛盾（上書き対象）／ ❓正典に記載なく要確認

## サマリ：Claude が独自に決めた / 既定で埋めた候補（要確認）

最も「勝手に決めた」色が濃いのは次の通り。

- 🟥 **TestContainers** — `implement-from-issue` の結合テスト欄に「実 DB。**TestContainers 等**」とあるだけ。CLAUDE.md にも frontend ルールにも無く、スキル文中で Claude が例示・前提化した唯一の要素。
- 🟨 **FE フレームワーク/ビルド系の既定値**（Vite / React Router / Material UI / Redux Toolkit / Axios）— いずれも CLAUDE.md「要件未指定時の標準スタック」の既定で、**frontend 正典（Next.js / App Router / Zustand）と矛盾**。実質 Claude が埋めた既定値が、後から来た正典に上書きされる関係。
- 🟨 **BE/テスト/静的解析の具体ライブラリ**（JUnit5・Mockito・JaCoCo・SpotBugs・Checkstyle・PMD・Istanbul 等）— すべて「未指定時の標準スタック」既定。チームの明示要件としては確認が取れていない。
- 🟨 **Playwright MCP（E2E）** — 既定かつスキルで**必須ゲート化**されているが、frontend 正典では「FE repo に E2E を含めない（AWS デプロイ後の別工程）」と矛盾。

## 注記

- 🟨「既定（Claude 提案）」は CLAUDE.md の章題どおり**要件が未指定のときのフォールバック**。チームが要件・設計で個別指定すれば上書きされる。FE 系の 🟨 は frontend 正典に既に上書きされている（⚠️）。
- 🟥「スキル内決定」は CLAUDE.md・正典のどこにも根拠が無く、スキル文面のみに存在する。正規の標準スタック／ルールへ昇格させるか、削除するか判断が必要。
- 本表の区分は出典の所在と framing からの推定。チームが意図的に選んだか Claude が埋めたかの最終確定は、原典（要件素材・チーム合意）との突合が必要。
